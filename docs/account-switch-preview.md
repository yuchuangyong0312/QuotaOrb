# Codex 账号切换测试版

版本：2.1.0-preview.8。稳定版 2.0.0 不含此功能。开发验证已覆盖合成账号的独立授权、保存、切换和恢复；真实 Codex 桌面 A→B→A 的验收仍待完成，不把进程启动等同于桌面账号验证成功。

## 使用步骤

1. 从托盘退出旧的额度管理工具，再运行测试版 `QuotaOrb.exe`。两个版本默认使用同一个本地资料目录，不要同时运行，也不需要导入或复制账号资料。
2. 在额度管理选中账号 A，点击 **授权切换登录**，在官方网页登录对应账号。完成后工具核对账号和额度，将独立的切换登录加密保存。此步骤可以保持 Codex 正在运行。
3. 选中账号 B，使用同样入口授权。无需在 Codex 桌面注销账号 A。额度查询授权与切换登录独立，不能用“额度能查到”代替这一步。
4. 保存完成后，从 **Codex 托盘菜单退出**，并关闭仍在运行的 Codex CLI / IDE 任务。在额度管理中选择账号，点击 **切换并打开 Codex**。
5. 工具核验目标身份和额度后，使用 Windows 注册入口打开 Codex。请核对 Codex 中的实际账号；提示“已打开”只代表登录文件身份一致并观察到桌面进程启动。

首次登录可能仍需密码和验证码。已保存的官方登录状态有效时，后续切换不需要再次输入。授权过期或服务器使旧令牌失效后，需再次点击 **授权切换登录**。网页授权必须选择与所选条目一致的账号和工作区。

切换区域的授权进度和操作结果跟随当前选中的账号；授权其他账号不会覆盖其提示。重启工具后根据每个账号各自的缓存显示是否已保存切换授权，保存状态不代表服务端登录一直有效，实际切换时仍会核验。

旧版“保存当前桌面登录”以及自动保存的退出账号记录，不等于独立切换授权。存在缓存文件不会直接启用切换；无法确认授权来源的旧记录会提示先点击“授权切换登录”，原记录仍保留。此前通过独立授权留下的待首次切换标记会被识别，无需重复授权。新版将授权来源与待首次切换状态分别保存，首次启动、令牌更新和重启工具不会丢失已确认的授权来源。

**退出程序和退出登录不同。** 日常切换时只需从 Codex 托盘退出程序。在 Codex 账号菜单点击“退出登录”可能作废此前保存的登录；恢复本地文件无法解除服务端作废。旧版按“退出登录、登录下一个账号”的方式收集的登录如果已经失效，需要逐个重新授权。

## 失败恢复

- Codex 仍在运行：停止切换，不强制终止进程。
- 目标登录失效、身份不符、已用完额度或启动失败：尝试恢复切换前的登录，并保留核验时更新的目标登录缓存。
- 服务端明确返回登录失效时提示重新授权；普通网络失败提示重试，不把它断定为账号失效。
- 独立授权被取消、选错账号或核验失败：保持已有切换登录和正在使用的桌面登录不变。
- 程序意外退出或无法安全恢复：保留加密恢复记录。退出 Codex 后，点击 **恢复上次登录**。
- 如果失败后已经自己登录了其他账号，可在退出 Codex 后点击 **保留当前登录**，放弃旧恢复操作并保留现有登录文件。
- 检测到新的、不属于这次操作的登录时，不自动覆盖。恢复本地文件不能使服务端已经失效的令牌重新有效。

## 支持范围与存储

此预览版仅识别 Windows 包 `OpenAI.Codex_2p2nqsd0c76g0` 的 `26.1007.2314.0`、`26.1007.9446.0`，以及 CLI `0.162.0-alpha.17.2`。后续版本需重新验证兼容性；不支持自定义 `CODEX_HOME`、keyring/auto/加密桌面登录存储或 API Key 登录。

桌面登录和未完成操作记录存放于 `%LOCALAPPDATA%\QuotaOrb\desktop-logins`，使用当前 Windows 用户的 DPAPI 加密，并限制目录权限。正常账号导出与仅含 EXE 的软件备份不包含这些 OAuth 登录状态。不能跨 Windows 用户或重装系统直接复用加密缓存。

切换时先保存当前账号最新登录，再安装目标登录，由官方后台组件在原登录文件中完成核验及必要续期。该组件结束后才启动桌面端，避免同时运行两个更新同一登录令牌的组件。

“授权切换登录”使用全新的独立 `CODEX_HOME`，不复制或续期正在使用的桌面令牌，也不调用退出登录接口。官方组件在仅当前 Windows 用户可访问的临时目录写入登录文件；核验结束并停止组件后读取最终状态，加密保存到登录缓存，并删除整个临时目录。失败和取消也会清理；进程异常结束时，下次启动会清理残留的本工具授权目录。该临时目录不属于软件备份。

新授权在首次成功启动之前优先于同账号的旧桌面登录，退出旧会话或重启工具不会覆盖它。切换失败时保留新授权用于重试，并恢复之前独立的桌面会话；成功启动后再跟踪桌面组件更新的登录状态。

工具不替换整个 `.codex` 目录，不改写聊天数据库、项目、技能、插件或配置文件。云聊天和工作区权限仍属于相应账号；本地聊天能否继续必须通过真实桌面验收确认。

## 人工验收

先完成当前 Codex 工作，再使用两个自己的账号检查：

- 通过工具分别授权账号 A、B，确认错选账号时会拒绝保存，且授权 B 后 A 的登录仍可使用。
- B 退出后切换 A，再由 A 退出后切换 B；两次都确认 Codex 实际邮箱正确、额度属于对应账号。
- 确认原有本地聊天、项目、技能和配置仍可见，并检查哪些云内容因账号权限发生变化。
- 退出并重新打开 Codex，确认仍保持目标账号。
- 记录仅含测试结论的结果，不提交登录文件、令牌、账号数据库或真实账号截图。

本机程序与用户指定的软件备份同步使用同一个测试版 EXE，并保留修改前的 2.0.0 程序。真实桌面往返验收通过后，再考虑公开发布；本机测试更新不代表已完成全部验收。
